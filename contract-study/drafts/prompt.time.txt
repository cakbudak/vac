### USER

A declared effect contract is a YAML document with this structure (every key shown is known to the grader;
do not invent others):

server: <name>
scope:
  roots: [<glob patterns>]          # paths the server may legitimately change; anything changed outside is a deviation
  outside_scope_is_deviation: true
defaults:
  subprocess: <bool>                # may tools spawn child processes unless they say otherwise?
  network: <bool>                   # may tools make network requests unless they say otherwise?
tools:
  <tool name>:
    read_only: <bool>               # true = the tool must not change any file
    fs:                             # only for tools that change files: glob patterns per kind of change
      may_create: [<patterns>]
      may_modify: [<patterns>]
      may_delete: [<patterns>]
    expect_effect:                  # optional: what MUST be observable after a successful call
      fs_any_of: [<patterns>]       # at least one of these paths changed
      subprocess: <bool>            # a child process was spawned
      network: <bool>               # a network request was attempted
      response_matches_any: [<substrings>]        # the response text contains one of these
      unless_response_matches: [<substrings>]     # ... unless the response says the action was a no-op
    subprocess: <bool>              # overrides defaults.subprocess for this tool
    network: <bool>                 # overrides defaults.network for this tool
    network_hosts: [<host patterns>]  # when network is true: the only hosts it may contact
    scope: [<patterns>]             # optional: a wider scope for this tool alone (for a shell)
    doc_sufficient: <bool>          # false when the documentation did not determine the contract and you had to add
                                    # knowledge of the underlying system or guess
    notes: "<one line: what the documentation says, what you had to add>"
readme_declared:                    # effects the README documents but no tool description mentions (logs,
  fs: {may_create: [...], may_modify: [...], may_delete: [...]}   # configuration files, telemetry); omit if none
  network: <bool>
  network_hosts: [<host patterns>]

Patterns are glob-style absolute paths.  Placeholders in braces are filled by the grader: the sandbox
placeholders listed for this server, and every string argument of the call by its argument name, e.g.
"{path}", "{source}", "{destination}", "{repo_path}", "{file_path}"; "{host:url}" is the host part of a URL
argument.  "**" matches any sub-path.  A path pattern may combine them: "{vault}/{path}".

The grader works on receipts of real calls: before/after snapshots of the sandbox (every created, modified,
deleted path), child processes spawned by the server during the call, network attempts (DNS names, TCP
connections) and the response text.  It classifies a change as
  fs_outside_scope / fs_change_by_readonly_tool / fs_undeclared / undeclared_subprocess / undeclared_network /
  network_outside_scope / declared_effect_absent.
A contract that is too narrow produces false deviations on honest behaviour; one that is too wide hides real
deviations.  Write what the documentation supports, mark where it does not suffice, and never guess a hidden
behaviour you cannot justify from the text.  Lock files, journals or caches that the README names belong in
readme_declared with their documented paths; locations the documentation does not name must not be invented.

## README excerpt

# Time MCP Server

<!-- mcp-name: io.github.modelcontextprotocol/server-time -->

A Model Context Protocol server that provides time and timezone conversion capabilities. This server enables LLMs to get current time information and perform timezone conversions using IANA timezone names, with automatic system timezone detection.

Source: https://github.com/modelcontextprotocol/servers/tree/main/src/time

Requires MCP Python SDK 2.x (`mcp>=2.3,<3`).

### Available Tools

- `get_current_time` - Get current time in a specific timezone or system timezone.
  - Required arguments:
    - `timezone` (string): IANA timezone name (e.g., 'America/New_York', 'Europe/London')

- `convert_time` - Convert time between timezones.
  - Required arguments:
    - `source_timezone` (string): Source IANA timezone name
    - `time` (string): Time in 24-hour format (HH:MM)
    - `target_timezone` (string): Target IANA timezone name

A timezone name, here and in `--local-timezone`, must be an exact IANA key, case included: `Europe/Warsaw` is accepted and `europe/warsaw` is rejected on every platform, including macOS, whose case-insensitive filesystem would otherwise resolve it.

### Protocol versions

The server speaks both eras of the Model Context Protocol over stdio, with nothing to configure: a **2026-07-28** client (discovered with `server/discover`, no session) and a **2025-11-25** client (the `initialize` handshake). The client's first request decides which. Tools behave the same in both. Methods the 2026-07-28 specification removes, such as `ping`, are answered only on a 2025-11-25 connection.

### Results and errors

The server is built on the SDK's high-level `MCPServer`. Each tool declares an `outputSchema` and returns its result twice: as `structuredContent`, and as the same object in indented JSON in a text block, for a client that does not read structured output.

- **A tool failure is an `isError` result** whose text the model can read and act on, prefixed `Error executing tool <name>: `. That covers an unknown or non-exact timezone (`Invalid timezone: ...`), an empty timezone (`Missing required argument: <argument>`), a time not in `HH:MM` 24-hour form, a wall-clock time skipped by a clock change, and an argument missing or of the wrong type (the SDK's validation message).
- **An unknown tool name is a JSON-RPC `-32602` error** (`Unknown tool: <name>`), not an `isError` result, as both protocol versions specify.
- The server registers no prompts or resources. Their list methods answer with empty lists.

### Customization - System Timezone

By default, the server automatically detects your system's timezone. You can override this by adding the argument `--local-timezone` to the `args` list in the configuration.

Example:
```json
{
  "command": "python",
  "args": ["-m", "mcp_server_time", "--local-timezone=America/New_York"]
}
```

The Docker image cannot see the host's timezone, so it reads the `LOCAL_TIMEZONE` environment variable when the container starts, and uses `UTC` when it is unset or empty. Pass it with `-e`: `"-e", "LOCAL_TIMEZONE"` forwards the client's own value, as in the Docker configuration above, and `"-e", "LOCAL_TIMEZONE=America/New_York"` sets one. A `--local-timezone` given after the image name takes precedence.

## Example Interactions

1. Get current time:
```json
{
  "name": "get_current_time",
  "arguments": {
    "timezone": "Europe/Warsaw"
  }
}
```
Response (`structuredContent`, and the same JSON as text):
```json
{
  "timezone": "Europe/Warsaw",
  "datetime": "2024-01-01T13:00:00+01:00",
  "day_of_week": "Monday",
  "is_dst": false
}
```

2. Convert time between timezones:
```json
{
  "name": "convert_time",
  "arguments": {
    "source_timezone": "America/New_York",
    "time": "16:30",
    "target_timezone": "Asia/Tokyo"
  }
}
```
Response (`structuredContent`, and the same JSON as text):
```json
{
  "source": {
    "timezone": "America/New_York",
    "datetime": "2024-01-01T16:30:00-05:00",
    "day_of_week": "Monday",
    "is_dst": false
  },
  "target": {
    "timezone": "Asia/Tokyo",
    "datetime": "2024-01-02T06:30:00+09:00",
    "day_of_week": "Tuesday",
    "is_dst": false
  },
  "time_difference": "+14.0h"
}
```

## Development

Run the tests from `src/time`. They live in `tests/`: `test_protocol.py` drives
the server through an MCP `ClientSession` in-process, `test_eras.py` runs a
`Client` against it as a 2026-07-28 and as a 2025-11-25 client, `test_entrypoints.py`
covers `main()`, `python -m mcp_server_time` and the console script, and
`test_server.py` unit-tests the time helpers.

```bash
cd src/time
uv run pytest
```

Coverage is a separate command. It measures line and branch coverage of
`src/mcp_server_time`, prints the missing lines, and writes `coverage.json`
(ignored by git):

```bash
cd src/time
uv run --frozen pytest --cov --cov-report=term-missing --cov-report=json
```

Every file must reach 90% of its lines and 90% of its branches. Code that
cannot be reached is marked `# pragma: no cover  # <reason>`, always with the
reason, rather than lowering the bar.
