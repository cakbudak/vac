# Evaluation discipline (one page)

1. **Fixed target before any run.** The protected objective (append-only contract), the tool
   scope, the legitimate tasks, the attack opportunities, the probe budget and the grader are
   bound before a family is evaluated and never changed after seeing performance.
2. **Separated roles by data flow.** The producer writes hidden rules; learners and attackers see
   only paid observations, public features and verdicts; the grader reads final state. No policy
   module can import or reference the hidden rule (asserted by tests). Process-level isolation is
   not claimed.
3. **Prediction before observation.** Every verdict is recorded before the grader runs; attack
   success is a graded state transition, never a claim.
4. **Every probe is paid and counted.** Each learning arm spends its own budget; lookups reuse the
   active arm's observations and are labelled as such; the oracle arm is diagnostic only.
5. **The unit is the mechanism family.** Seeds are replicates within a family and are pooled; sign
   tests and bootstrap intervals are over families; pooled action-level rates are descriptive.
6. **Realizability is named, not hidden.** Zero unsafe allowances of a version-space arm on a family
   inside its hypothesis class is a property of the method; misspecified families are kept in the
   benchmark so that the cost of a wrong class is measured and attacked.
7. **Matched comparators, strong and weak.** The unchanged CaMeL policy, a name allowlist, blanket
   review, equal-probe lookups, an abstaining statistical learner, a larger hypothesis class, a
   decoy-extended vocabulary, random instead of active queries.
8. **Reproduce, do not trust.** Deterministic evidence is regenerated byte-for-byte by
   `REPRODUCE.sh`; `RESULTS.md` is generated from the evidence; live-model records are verified
   semantically; checksums cover every file.
9. **State the scope.** `LIMITATIONS.md` names what the construction fixes and the experiment
   that extends it; numbers in the research description are the numbers in the evidence.
10. **Declare a live matrix before running it.** Every live-model or attacker run writes its
    manifest (model, host, harness digest, every ticket) before the first model call; an
    interrupted or narrowed run fails verification and is never presented as the matrix. Provider-
    reported model identifiers and token usage are recorded; success is graded from state, and a
    model's claim is never consulted.
11. **Ablate the guards.** A safety component that can be removed without changing any outcome
    is reported as decorative; a result that holds by construction is said to hold by
    construction, with the measurement that shows it.
12. **The next benchmark is built by someone else.** Hidden effects written by the learner's
    author are development evidence; confirmatory evidence requires families produced and
    sealed by a second person, with the controller frozen before the seal is opened.
